# SharePoint 同期の Excel 上限

`.xlsx`、`.xlsm`、`.xls` を検索 Index に登録する前に、次の上限を適用する。設定を省略しても既定値が有効。

| 環境変数 | 既定値 | 対象 |
| --- | ---: | --- |
| `SL_SYNC_MAX_EXCEL_SOURCE_BYTES` | 5,242,880 bytes (5 MiB) | すべての Excel ファイルの元データ |
| `SL_SYNC_MAX_EXCEL_XML_BYTES` | 20,971,520 bytes (20 MiB) | `.xlsx` / `.xlsm` のワークシート XML と共有文字列 XML の展開後合計 |
| `SL_SYNC_MAX_EXCEL_CHUNKS` | 300 | すべての Excel ファイルの Embedding 前のチャンク数 |

元データと XML の上限は Excel の内容を展開する前に判定する。チャンク上限は抽出後、Embedding API を呼ぶ前に判定する。上限超過はファイルの版と Index ごとに共有台帳へ記録するため、次回の同期ではバッチ選択前に除外し、後続のファイルを処理できる。ファイルを更新した場合、または該当する上限を引き上げた場合は、再び候補になる。ただし、別途設定された累計試行回数の上限に達したファイル版は引き続き除外される。ログにはファイル名、判定項目、実測値、上限を出力する。PDF のページ上限と処理経路は変更しない。

2026-09-14 の `test2.xlsx` は元データ約 4 MB、対象 XML 46,739,755 bytes で、XML 上限により展開・Embedding 前に除外される。実ファイルでの判定は、Azure を呼ばないローカルテストで確認した。
